# LWC Testing (Jest)

> Part of `reviewing-lwc` — see SKILL.md for the always-on Quick Reference and routing.

- Cover loading, data, and error states for every wire-driven component.
- **Test black-box: assert on rendered DOM and dispatched events, never on internal fields.** `expect(element.shadowRoot.querySelector('lightning-spinner'))` — not `expect(component.isLoading)`. Never add an `@api` property just to make state reachable from a test; that freezes implementation detail into the public contract.
- **An assertion against a `lightning-*` stub proves assignment, not rendering.** `sfdx-lwc-jest` replaces every base component with an inert stub (`src/lightning-stubs`) declaring its public props and nothing else, so `expect(combobox.value).toBe(id)` only re-reads the property the code under test just set and cannot fail for any reason involving real component behaviour. This passes the black-box rule above — a base component *is* in the DOM — so apply the **revert test** to every base-component assertion: would this still fail if the feature were deleted? If not, it is pinning an assignment. Assert instead on the inputs the real component derives its rendering from. When reporting a green suite as evidence, state which half it proves.
  ```js
  // BAD  expect(combobox.value).toBe(recordId)   // passes with the restore code deleted entirely
  // GOOD expect(combobox.options.some(o => o.value === combobox.value)).toBe(true)
  ```
- **Apply the revert test to every new assertion, not only stub ones:** revert the code under test once and confirm the assertion goes red. A test that stays green is decoration — delete it.
- **Jest traps that pass or fail for the wrong reason:**
  - `toEqual` on DOM nodes uses `isEqualNode`, so two different elements with the same markup are "equal" and a test about *which* element was used can never fail. Use `toBe`.
  - `jest.clearAllMocks()` does not drain queued `mockReturnValueOnce` values; use `mockReset()`. A test that passes alone but fails in the suite usually points at mock lifecycle, not the component.
  - `new CustomEvent('mousedown')` has no `button`, so a handler checking `event.button === 0` never runs; dispatch a `MouseEvent`.
  - LWC rewrites template-authored `id` values, and attribute selectors on stubs (`lightning-input[type=checkbox]`) match nothing. Query by `data-*` attribute or class, and assert the selector matched before asserting on what it found.
  - The `ShowToastEvent` stub does not export `ShowToastEventName`; listen for `lightning__showtoast`.
  - `sfdx-lwc-jest` ignores `apiVersion` in `.js-meta.xml` and cannot see the CSS cascade or layout, so an API-version bump or a styling fix is proven only in the org. A CSS-only module needs `css` in Jest's `moduleFileExtensions`.
- **Test at production size.** Fixtures of 1–3 rows cannot catch defects that appear at the real size (a 200-row cap, pagination, list rendering). Include one fixture at the size production sees; when a bug will not reproduce, scale the fixture before changing tools.
- **When a fix tightens a comparison** (substring to exact, `includes` to `===`), add a fixture copied from a real saved record, stray whitespace and casing included, and trim user-typed values at the split. Clean fixture strings pass both the old and the new code.
- **Reject any `__tests__` file still holding the CLI-generated placeholder** (`it('TODO: test case generated by CLI command...', () => expect(1).toBe(1))`). It passes forever and makes a defective component look covered.
- **Test the component in a connected state.** Wire adapters only provision data when the component is in the DOM — `document.body.appendChild(element)` *before* emitting wire mocks, or assertions silently pass against `undefined`.
- **Clean up in `afterEach` with `document.body.removeChild(element)`.** A component instance shared across tests lets state from one test corrupt the next.
- **Emit wire values via `@salesforce/wire-service-jest-util`**, not hand-rolled module mocks — the utility simulates the adapter lifecycle (data and error states) correctly.
- **Derive LDS mock JSON from a real UI API snapshot** (Workbench or developer console) for `getRecord`/related-list adapters. Hand-crafted mocks with the wrong shape cause silent failures. Store mock data under `__tests__/data/`.
- **`await flushPromises()` before asserting** after emitting a wire value — `Promise.resolve()` is insufficient to flush multi-tick async chains.
- Run via `npm run test:unit`.
